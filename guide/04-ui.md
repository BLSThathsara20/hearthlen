# UI

**What you are learning here.** The interface is the part a person can see, hear, and correct. For this project it stays a normal laptop desktop. The assistant is a small card and a place to talk, not a second operating system made of chat bubbles.

The visual brand, wallpaper, and boot screen wait until Phase 6. This file specifies behavior and layout so those can be skinned later without changing how the assistant works.

## The desktop

The screen looks like a simple computer.

- A panel along the edge, with the applications a person expects: files, browser, settings.
- Windows open on the desktop in the ordinary way. The assistant does not replace the file manager or the browser.
- Large type, few controls, a calm layout. English sentences are stored in string files with a language tag. Sinhala strings can be added beside them later.
- No terminal is required for daily use. Setup and recovery can use one. The person the OS is for should not have to.

LXQt is the desktop, as recorded in [06-decisions.md](06-decisions.md). The UI rules below are for that panel and for the assistant windows. They are not a separate shell.

## The panel

The panel carries three assistant pieces plus the usual clock and network icon.

- **Microphone.** Shows listening after the wake word, and shows idle the rest of the time. Choosing it starts a typed-or-spoken request without the wake word.
- **Text box.** Typing a sentence and confirming it runs the same path as speech. Voice and text are equal.
- **Screen-reading mark.** A small mark while the accessibility tree is being sampled. Pause learning, and the mark goes away. The mark is always visible when sampling is on. There is no hidden watch mode.

The wake word and the text box call the same skills. If speech-to-text is still unloaded, typed text still works. That is how Phase 2 can exist before Phase 3.

## The assistant card

When the assistant speaks, a small card appears. It shows one sentence. The spoken reply, once Piper exists, says that same sentence.

If the assistant needs a choice, the card has a couple of large buttons, such as **Yes** and **Not now**. The buttons are the confirmation. There is no tiny link and no wall of explanation.

The card is for one moment. It closes when the action finishes, when the person dismisses it, or after a short quiet period on a pure status line such as “Playing Shape of You”.

## Suggestions

A habit that is ready and safe can show one line: “Open your notes?”.

- One suggestion at a time. A stack of popups is a bug.
- Dismissing it updates the habit, as in [03-assistant-that-learns.md](03-assistant-that-learns.md).
- A suggestion never covers the middle of the person’s work. It sits with the card, at the edge.
- Risky actions are never “just a suggestion” that runs on a timer. They use the confirmation card and wait.

## Confirmation

The same card is used for delete, send, pay, and turning Wi-Fi off. The sentence names the action in plain words: “Turn Wi-Fi off?”. **Yes** runs the skill. **Not now** cancels and is logged.

Volume and brightness apply and are logged. They do not wait on a dialog. The person can still ask to undo a brightness or volume change in a later skill. Until an undo skill exists, the log is the record.

## What I’ve learned

A settings page, written in sentences:

- “On weekday evenings you set brightness to 30%.”
- “Graduation photos means Pictures/Graduation.”
- “Play some music means Shape of You on YouTube.”

Each row has **Delete**. The page has **Pause learning**. Pause stops new memories and stops screen reading. A short line on the page says that memories stay on this laptop.

The page is the trust screen. If a habit cannot be shown as a sentence, it does not belong in the store.

## First boot

The first session with the assistant is a short setup, still in the same visual language.

1. The name is Hearthlen. First boot confirms it and stores it for the wake phrase.
2. Check the microphone with one sentence, once voice exists. Before voice exists, this step is skipped and the text box is the path.
3. A short explanation: the assistant learns routines on this laptop, the panel mark shows when it is reading the front window, and the list can be viewed, deleted, or paused.

No account. No network requirement for this setup. Updates and YouTube need the network later. The assistant itself does not.

## Speaking and typing

| Person does | System does |
|---|---|
| Says the wake name and a request | Wake word, then speech-to-text, then the same skill path as text |
| Types in the panel | Skill path, no microphone |
| Says “not that” or presses Not now | Log a correction or a cancel |
| Opens What I’ve learned | Show the habit sentences |

Before Phase 3, the spoken column is absent and the typed column is the product. The card copy is the same in both.

## What the person should feel

They open the laptop and it is a computer. They ask for a song, a file, or a brighter screen, and that happens. After a while they can ask more vaguely, because the laptop has seen the specific choice before. When something is about to be deleted, sent, paid, or disconnected, the laptop stops and asks. When they wonder what it knows, the list is in settings, in sentences, and a delete button works.
